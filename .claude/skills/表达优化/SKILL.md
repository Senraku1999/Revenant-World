# 表达优化

全流程文本表达质量审查与优化管线。对标点、AI写作痕迹、叙事逻辑、动作闭环进行全面审查，并自动执行可修复项。

## 适用文件类型

- 角色卡 JSON（char_dialogue_examples、overview、origin 等叙述字段）
- 简介 .md
- 开场白 .md
- 小说化内容 .md
- 世界观卡 / 事件卡 JSON 与 .md

## 管线流程

按序执行以下四个阶段，前一阶段通过后再进入下一阶段。

### 阶段零：确定目标文件

若用户未指定文件，默认处理当前会话中最近创建或修改的 `.json` 与 `.md` 角色文件。

---

### 阶段一：标点审查（一级 → 二级 → 三级）

按序执行三级标点审查，前一级通过后再进入下一级。

#### 1a. 一级审查（自动脚本 · GB/T 15834 国标）

```bash
npx tsx "创作者文件/审查文件/标点审查/一级审查/一级审查.ts"
```

将脚本输出的违规标记为 **P1类问题**（Punctuation / 国标）。

#### 1b. 二级审查（人工核查 · 项目追加收紧）

读取规则文档 `创作者文件/审查文件/标点审查/二级审查/标点符号二级审查.md`，然后对目标文件逐条对照核查以下收紧项：

| # | 核查项 | 规则 |
|---|--------|------|
| 1 | 破折号 `——` | 仅限对话引号 `""` 内，引号外一律改逗号或冒号 |
| 2 | 省略号 `……` | 仅限对话引号 `""` 内，引号外一律禁止 |
| 3 | 引号形式 | 仅允许 `""`（U+0022 英文直双引号），禁用 `""`（U+201C/U+201D 中文弯引号） |
| 4 | 分号 `；` | 仅并列关系（互换测试：前后互换语义不变），因果/递进/转折/时序改用逗号或句号 |
| 5 | 感叹号 `！` / 问号 `？` | 对话内保留，叙述中禁止 |
| 6 | 冒号 `：` | 仅限枚举（`X：A、B、C`）、解释（`X：Y说明`）、引述（`说："..."`），其余场景避免 |
| 7 | JSON 非对话字段 | 禁止 `—`（U+2014 em dash），仅对话字段 `char_dialogue_examples[].response` 内 `——` 合法 |

将违规标记为 **P2类问题**（Punctuation / 项目收紧）。

#### 1c. 三级审查（自动脚本 · 三步法全标点测试）

```bash
npx tsx "创作者文件/审查文件/标点审查/三级审查/三级审查.ts"
```

**三级审查防护（必须执行）：**

脚本运行完毕后，必须验证：

1. 三级审查输出文件已生成：`创作者文件/审查文件/标点审查/三级审查/三级审查结果.txt`
2. 若脚本返回非零退出码或输出文件不存在 → **立即停止管线，报告故障，不得静默进入下一阶段**
3. 用 `grep` 提取目标文件的三级审查标记，确认"句号应改逗号"项已被读取和逐条审查

```bash
# 防护验证
test -f "创作者文件/审查文件/标点审查/三级审查/三级审查结果.txt" || echo "FAIL: 三级审查输出缺失"
# 提取目标文件的句号问题
grep -A3 "目标文件名" "创作者文件/审查文件/标点审查/三级审查/三级审查结果.txt" | grep "原句"
```

将违规标记为 **P3类问题**（Punctuation / 三步法）。

#### 1d. 句号密度检查（手动，必须执行）

```bash
# 统计目标文件的句号/逗号比例
grep -o '。' 目标文件 | wc -l  # 句号数
grep -o '，' 目标文件 | wc -l  # 逗号数
```

**判断标准**：句号:逗号比例低于 1:3 → 短句过多，句号滥用。正常叙述文比例约为 1:4 到 1:6。

**手动朗读测试**：通读全文，标记连续三句以上长度相近的短句（每句≤15字且以 `。` 结尾）。

**常见句号滥用场景**：
- 同一角色的连续动作被句号切断 → 改逗号合并
- 短语/从句被句号孤立成单句 → 改逗号或重构
- 形容词/副词片段独立成句 → 合并到前后句

此项标记为 **R类问题**（Rhythm）。

#### 阶段一汇总

P1（国标）+ P2（项目收紧）+ P3（三步法）+ R（节奏）合并输出为 **P类问题**（Punctuation），按 T0/T1 分级。此阶段为机械检测 + 人工核查，零容忍。

---

### 阶段二：AI味检测报告（humanizer-zh）

对目标文件执行 `humanizer-zh` skill，**仅检测不修复**。基于 Wikipedia "Signs of AI writing" v2.5.1，覆盖 29 类 AI 写作痕迹模式，输出结构化检测清单供人工复核后手动修改。

**执行指令：**
调用 `humanizer-zh` 时明确告知：
- **仅检测模式**：逐条列出发现的 AI 痕迹，不直接改写原文
- **项目引号规范**：本项目唯一合法引号为英文直双引号 `""`（U+0022），禁用弯引号 `""`（U+201C/U+201D）
- **角色 voice 保护**：角色卡为创造性写作，口癖、性格化措辞不属于 AI 味

**输出格式（每条必须包含三项）：**
```
【问题类型】{模式名}
【位置】{文件名} → {字段/段落} → "{含命中文段的原文上下文}"
【修改建议】{具体改写方向，不改动事实信息与角色 voice}
```

核心覆盖类别：
- 内容模式：过度强调意义/知名度、肤浅分析、宣传式语言、模糊归因、公式化挑战章节
- 语言语法：过度使用的 AI 词汇、系动词回避、否定式排比、三段式滥用、刻意换词、虚假范围、被动语态
- 风格模式：破折号/粗体过度使用、内联标题列表、弯引号、表情符号装饰、说服性权威措辞、预告性声明
- 交流模式：协作交流痕迹、知识截止日期免责声明、谄媚语气
- 填充与回避：填充短语、过度限定、通用积极结论、标题后碎片化引导句

将检测结果按严重程度标记为 **A类问题**（AI Slop）：
- T0：确定是AI痕迹，必须手动修改
- T1：疑似AI痕迹，建议手动修改
- T2：风格选择，可选优化

---

### 阶段三：文笔逻辑审查（prose-reviewer agent）

调用 `prose-reviewer` agent，从以下维度逐文件审查：

1. **动作逻辑**：人物动作是否连贯、物理上可行
2. **词汇自然度**：有无生硬措辞、翻译腔
3. **句式节奏**：长短句搭配、段落呼吸感
4. **比喻恰当性**：禁止抽象→抽象比喻，至少一端为实物
5. **情感合理性**：人物反应是否符合身份和处境
6. **冗余表达**：可删减的重复或啰嗦

同时交叉验证开场白六项机械核查（若有开场白文件）：
- 肢体逻辑：动作描写是否可执行
- 能力一致：角色展现的能力是否与 JSON 设定一致
- 武器在场：武器是否存在且描写正确
- 时间连续：时间线无跳跃矛盾
- 空间锚定：场景物理空间前后一致
- 动作闭环：无半途消失的动作

将发现标记为 **L类问题**（Logic & Narrative）。

---

### 阶段四：标点复核

修复完成后重新运行阶段一的标点脚本，确认修复过程未引入新的标点违禁。

```bash
npx tsx "创作者文件/审查文件/标点审查/一级审查/一级审查.ts"
npx tsx "创作者文件/审查文件/标点审查/三级审查/三级审查.ts"
npx tsx "创作者文件/审查文件/自动检查.ts"
```

## 快捷模式

若用户说"快速表达优化"，跳过阶段三（文笔逻辑审查），仅执行：
标点审查 → AI味检测报告（humanizer-zh） → 标点复核

若用户指定单文件（如"表达优化 薰开场白"），只对该文件执行全流程。
