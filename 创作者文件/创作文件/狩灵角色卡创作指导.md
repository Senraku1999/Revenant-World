# 狩灵世界观 · 角色卡创作指导

## 零、创作总纲

角色卡不是档案，是给 AI 演员的演出说明书。AI 拿到你的卡，要能直接"演"出来——而不是"知道"这个角色是谁。

**三条铁律**：

1. **写行为，不写标签。** "高冷"等于什么都没说。"对方受伤时嘴硬但在门口守着"——AI 可以直接拿去演。
2. **嘴上说的 ≠ 手上做的 ≠ 心里想的。** 这道裂缝越宽、写得越具体，角色越像真人。身体比嘴诚实。
3. **不写情绪，写身体。** 不是"她很害怕"——是"左膝发软，手掌抠住门框的木刺"。

**一句话自检**：读完这段描述，你能在脑子里看到一个具体的画面吗？如果不能——删掉重写。

详细规则见 §二（写实原则、人话写作五原则、JSON 文风约束）。

## 二、角色卡结构：十段式 Token 预算

角色卡 JSON 按字段拆为九个段落，每段有独立 token 预算（tiktoken `cl100k_base` 编码，计数对象为 JSON）。

| # | 段名 | JSON 字段 | 区间 |
|:--:|------|------|:--:|
| ① | **外观** | char_persona（gender/age + height/weight/hair/face/features/clothing） | **[50, 150]** |
| ② | **武器** | char_persona.appearance.weapon | 无实体武器精确写 `无。`；有实体 **[0, 100]** |
| ③ | **概述** | char_description.overview | **[0, 100]** |
| ④ | **性格** | char_personality（core_traits / strengths / flaws / quirks） | **[50, 150]** |
| ⑤ | **经历** | char_description（origin + current_mission） | **[50, 250]** |
| ⑥ | **基础能力** | char_basic_abilities（灵力/灵视/身体素质） | **[0, 150]** |
| ⑦ | **特殊能力** | char_special_abilities | 段级不设限；**单条 [0, 150]**（单键对象序列化成本，含键名） |
| ⑧ | **角色关系** | char_relationships | 段级不设限；**单条 [0, 150]**（不纳入总计） |
| ⑨ | **对话示例** | char_dialogue_examples | **[200, 400]** |
| — | **总计** | ①~⑦ + ⑨ 合计（不含⑧角色关系） | **[700, 1250]** |

预算基于 2026-07-28 全量中文 JSON 校准（cl100k_base）。上限贴近现役最大值，防止膨胀；下限为防呆线，拦截空字段与漏写事故。武器哨兵值 `无。` 走精确匹配，非哨兵值走区间。开场白独立于 JSON 预算，区间 [900, 1100]。

## 三、字段编写规则（按九段顺序）

> **全卡去重原则**：整张角色卡各字段之间不得重复相同信息。char_status 已声明的当前派系、职务、状态标签，origin 不得复述。过去身份作为故事背景或分类名词作为语法主语引出全新信息，允许保留。overview 作为角色核心概述，身份与 faction 的交叉属正常表述。

> **对照现有角色卡原则**：填写任一字段前，翻阅至少三张现有角色卡的同字段。字段定义的不是"你认为这里该写什么"，而是"同类角色实际上在这里写了什么"。常见越界：overview 写成 core_traits 的展开版、strengths 写成 special_abilities 的缩写版。每个字段回答一个不同的问题。

> **写实原则（四类禁手）**：叙述应平实，让动作和对话本身传达信息，不在旁边加注解。
>
> **① 机械面部描写**：用"嘴角""眼瞳""弧度"做表情填空。角色说了什么、做了什么，本身就传达情绪。
>
> **② 声音/语气的明喻包装**：用"X得像Y"给每句对话加滤镜。对话内容和上文动作已经传递了语气。
>
> **③ 替读者下结论**：写完一个意思后，再用比喻或解释复述一遍。写到"保护欲强"就停。
>
> **④ 抽象对抽象比喻**：两端都没有实物锚点的比喻，无法可视化。至少一端应为实物。
>
> **人话写作五原则**（从全量角色卡修改中提炼）：
>
> **① 灵力回路 = 裸效果，零包装**：删除"激活回路时""回路关闭或灵力耗尽时消散""强度随灵力输出提高""受灵力储备限制"等一切可推导的模板废话。只写能力产生的效果。坏例：`激活回路时，从小臂铠甲生长白色棘刺。棘刺仅存在于回路激活期间，回路关闭时消散。` 好例：`从小臂铠甲和拳锋生长白色棘刺。硬度随每次被击碎或折断后再生而逐渐增加。`
>
> **② overview 第一句 = 身份标签 + 一句话特质**：开门写组织归属和身份定位，方便 ST 快速检索。好例：`晨昏事务所成员，防御专家，安保和护送任务的可靠人选。`
>
> **③ origin 不得跳跃**：按时间线写全"觉醒方式 → 如何进入当前组织 → 关键转折事件 → 如何到达现状"。禁止一句话跳跃式概括。
>
> **④ 禁止 AI 式情感升华句**：叙事字段的结尾禁止概括性总结。`"那份沉默是她所允许的最接近信任的距离"` `"不是歌词催泪，是一种直接从胸口传过来的东西"` `"她的信任没有错付"` ——全是 AI 高频模式。用具体行为或观察替代。
>
> **⑤ personality 用标准中文陈述，不模仿角色口吻**：personality 是说明书字段。好例：`行动先于思考，对挑衅缺乏克制` 而非 `先动手后动脑，一被挑衅就上钩`。
>
> **JSON 文风约束（两线原则）**：
>
> JSON 字段分为两类，文风要求不同：
>
> **说明书字段**（personality / 回路 / overview / 基础能力）→ 删除一切可推导的废话。标准中文陈述，不模仿角色口吻。
>
> **叙事字段**（origin / current_mission / relationships）→ 写具体行为与事件，禁止抽象情感概括。relationships 允许角色视角。
>
> dialogue_examples 采用第三人称叙述体，不受说明书语调约束。简介和开场白采用叙事语调。

### ① 外观段 — char_persona

权重 ⭐⭐ | 预算 [50, 115]

包含：`gender`、`age`、`height`、`weight`、`hair`、`face`、`features`、`clothing`。

#### Face

详见 `创作者文件/创作文件/Face描述标准.md`。

核心规则摘要：
- 仅描述在任何时刻都能看到的固定物理特征
- 语序：脸型 → 肤色 → 五官特征 → 瞳色 → 标记
- 有辨识度的才写，没辨识度的不强加。仅有瞳色不是缺陷
- 禁止气质形容词、一次性表情、比喻、化妆、行为变化描述
- 新建角色时优先选择标记或五官作为锚点，避免与同阵营角色大面积重复

#### Hair

`[颜色][长度/发型][，补充描述]`。结尾加句号。

> 简单型：`粉色长发。`
>
> 复杂型：`银白色长发微卷发尾，低马尾。`

#### Clothing

详见 `创作者文件/创作文件/Clothing描述标准.md`。

核心规则摘要：
- 从上到下、从内到外，逗号分隔，结尾句号
- 主体链：`上身(内层→外层→腰带/束带/领带) → 下身 → 袜类 → 鞋类 → 尾部配饰`
- 配饰在句号后独立描述
- 禁止行为描述、武器混入、条件性穿着
- 同类角色通过配饰、颜色锚点、单件异常来区分

#### Features

记录显著身体标记（伤疤、纹身、义肢等），无则写 `无。`，不省略字段。

#### 句号规则

`face`、`clothing`、`hair`、`weapon`、`features` 结尾均加句号。

### ② 武器段 — weapon

权重 ⭐ | 预算：无实体 `无。`（固定值），有实体 [0, 85]

- **有实体武器**：描述武器名与核心性能，结尾加句号
- **无实体武器**：精确写 `无。`

不附加防身刀具、测试枪械或简易武器。武器出力的放大效果、嵌入回路的性能归入 weapon 字段。

### ③ 概述段 — overview

权重 ⭐⭐⭐ | 预算 [0, 60]

详见 `创作者文件/创作文件/Overview描述标准.md`。

核心规则摘要：
- AI 建立角色印象的第一入口。回答：什么人、什么身份、什么特点
- **首句以归属标识开头**，方便 ST 快速检索。一句为主，逗号分隔语义单元
- **禁止**：`游魂` `罪灵` 等分类标签（非具体身份）、分号 `；`、文学化比喻、纯 origin 压缩、纯性格描述

#### 按阵营的标准格式

以下格式从全部 54 个角色 overview 中归纳，为现行惯用写法：

| 阵营 | 格式 | 示例 |
|------|------|------|
| 狩灵协会 | `狩灵协会X科[职务]，[特质]。` | `狩灵协会2科科长，表面懒散，实战中展现出极端的战斗本能与精准判断。` |
| 事务所 | `[事务所名][职务/成员]，[特质]。` | `晨昏事务所成员，防御专家，安保和护送任务的可靠人选。` |
| 工坊 | `[工坊名]坊主，[特质]。` | `锻心工坊坊主，刀匠宗师，铸造的刀以经久耐用著称。` |
| 锈钟-指针 | `锈钟指针[时针/分针/秒针]，[特质]。` | `锈钟指针分针，双重人格。白天明做上班族，入夜后月接管身体，主持指针事务。` |
| 锈钟-发条/齿轮/表盘 | `[帮派][职务]，[特质]。` | `齿轮二掌柜，操持情报榨取，手段无论体面与否。` |
| 四色音 | `四色音的[担当]，[特质]。` | `四色音的主唱与作词，歌声带着灵力，能让人感受到她唱出来的情绪。` |
| 前协会成员 | `前狩灵协会X科[身份]，[现状]。` | `前狩灵协会4科成员，独自追猎烬。` |
| 通缉犯 | `[具体罪名]，[特质]。` | `连环杀人犯，把每次杀戮当作品来设计。` |
| 无组织（职业身份） | `[职业/身份]，[特质]。` | `罪灵猎人，靠罪灵的赏金过活，将狩灵协会当作客户。` |
| 无组织（家族身份） | `[家族身份]，[特质]。` | `花坂家幼女，福冈高三学生，天生灵能者。` |

#### 归属标识定义

**归属标识** = 组织/帮派/工坊名 + 职务/成员。`游魂` `罪灵` 是 char_identity 分类标签，不是具体身份，禁止作为 overview 的归属标识使用。`锈钟` 作为顶层联盟名，在帮派名已出现时省略（如 `齿轮二掌柜` 而非 `锈钟齿轮二掌柜`），指针三人因跨帮派属性保留 `锈钟指针` 前缀。

#### 身份标签判断

有明确组织归属的，写组织+身份（如 `来生事务所成员`）。无组织但有前身份的，写前组织（如 `前狩灵协会4科成员`）。既无组织也无前身份的，写职业或家族身份（如 `罪灵猎人` `花坂家幼女`）。

### ④ 性格段 — char_personality

权重 ⭐⭐⭐ | 预算 [50, 150]

#### core_traits

3 个关键词，用 `；` 分隔，结尾加句号。优先用带张力的特质组合。**禁止叙事句、文学修辞。**双重人格角色可用 `人格A: ... / 人格B: ...` 格式。

> `善感；耐心；有底线。`
>
> `冷静；过度理性；淡漠。`

#### strengths

2-3 个短词组，用分号分隔。写具体可观测的能力。**禁止叙事句、比喻修辞、情感化语气。**

> `和声融合；化解紧张；早一步照顾。`

#### flaws

1-3 个短词组，用分号分隔。写具体可观测的行为模式。**禁止叙事句、翻译腔句式、临床术语、商业用语。**

> `压抑到临界点时突然爆发；不会拒绝；忽略自己。`

#### quirks

1-2 个短句。写具体可观测的小动作或习惯。**禁止叙事句、性格描述、能力效果、解释性后缀。**

> `缝衣服时哼歌。`

### ⑤ 经历段 — char_description

权重 ⭐⭐ | 预算 [50, 250]

char_description 包含三个字段，形成一条叙事链：**overview（现在是谁）→ origin（怎么变成这样的）→ current_mission（往哪走 / 在做什么）**。三字段各有独立职能，同一信息不在其间冗余。

#### 5.1 三字段职能定义

| 字段 | 回答的问题 | 时态焦点 | 长度参考 |
|------|-----------|----------|----------|
| overview | 此时此刻，这个人是什么角色、有什么标志性特征？ | 现在 | 1句 |
| origin | 经历了什么关键事件才走到 overview 所描述的现在？ | 过去 | 1-6句 |
| current_mission | 当前在做什么、往什么方向走？ | 现在及近期未来 | 1-2句 |

#### 5.2 overview

详见 `创作者文件/创作文件/Overview描述标准.md`（见上文③）。此处补充三字段协同视角下的交互规则：

**与 origin 的边界**：overview 不写时间线叙述。如果一句话以"XX岁时""毕业后""觉醒后"开头，它属于 origin。
- 正例：`以按摩梳理灵力回路的理疗师。`（身份快照）
- 反例：`童年觉醒御灵后拒绝将能力投入正面战斗...`（时间线叙述侵入 overview）

**与 current_mission 的边界**：overview 写"谁"，current_mission 写"做什么"。两字段不应出现几乎相同的句子。
- 正例：overview `棘刺越碎越硬的近身格斗者，护短，藏不住事。` / current_mission `为来生事务所承接战斗委托。保护雨的安全。`
- 反例：overview `一人运营，只接最低限度的委托。` / current_mission `独自开设事务所，只接最低限度的委托。`（核心信息高度重叠）

**overview 中允许重叠 char_status/faction 的身份信息**，这是全项目实际惯例。不允许的是 origin 的浓缩复述。

**五种句式模式**（从全部角色卡中归纳）：

| 模式 | 句式 | 实例 | 适用 |
|------|------|------|------|
| 身份+特征 | `[身份]，[特征或钩子]。` | `晨昏事务所所长，专接别人避开的委托，按自己的准则行事。` | 大多数角色 |
| 能力+定位 | `[核心能力/打法]，[身份或定位]。` | `棘刺越碎越硬的近身格斗者，护短，藏不住事。` | 战斗向角色 |
| 组织角色+贡献 | `[组织]的[职能]，[独特贡献]。` | `四色音的和声担当，舞台上每一套演出服都是她一针一线做的。` | 团队角色明确 |
| 身份+张力 | `[身份]，[矛盾的修饰]。` | `个人战斗力不突出但稳定可靠，新人眼里天生的导师。` | 有内在张力的角色 |
| 身份+代价 | `[身份]，[以代价换取的定位]。` | `苍白爪牙，以五倍速度燃烧生命，清楚自己还剩多少年。` | 以代价为核心 |

#### 5.3 origin

精炼关键信息。保留：时间、地点、关键事件、转折点。近期信息权重更高。

**必须按时间线写全四段式**：觉醒方式 → 如何进入当前组织 → 关键转折事件 → 如何到达现状。不得跳跃，不得一句话概括式省略。

**包含要素**（从全部角色卡中归纳，按权重排序）：

| 要素 | 何时必写 | 何时可省略 |
|------|----------|------------|
| 觉醒事件 | 觉醒情境影响角色定位 | 觉醒情境无特殊性 |
| 关键转折点 | 改变人生轨迹的事件 | 无重大转折 |
| 职业/身份轨迹 | 角色在不同组织/身份间流动 | 始终在同一角色中 |
| 因果链 | 某个原因解释了后来的选择 | 背景无需因果解释 |

**信息密度三档**：

| 密度 | 句数 | 何时使用 | 实例 |
|------|:--:|------|------|
| 轻量 | 1 | 背景简单，仅一个身份转变 | `原为修女，觉醒灵力后加入狩灵协会5科。` |
| 标准 | 2-3 | 包含觉醒+职业轨迹+一个转折点（最常见） | `前保安公司员工，在一次安保任务中觉醒灵力，防御本能展现出异常天赋，加入狩灵协会后三年内晋升为考官。` |
| 密集 | 4-6 | 多个生命阶段或多重转折，每个转折都是理解 overview 所必需的 | 薰、爱、天、雨 |

**密集 origin 的唯一准许条件**：每一句承载的因果节点都不多余。删掉一个转折点后读者仍能理解 overview，则删除。

**年龄规则**：origin 中涉及的工作/从业年龄须 ≥ 18 岁。觉醒年龄不受此限，世界观设定中灵能觉醒集中在青春期。

#### 5.4 current_mission

当前时间点状态，给对话提供起点。

**两个子类型**：

| 子类型 | 回答的问题 | 实例 |
|--------|-----------|------|
| 日常任务 | 他在做什么事？ | `经营万事屋，处理委托。` |
| 深层驱动 | 他在追求什么/害怕什么？ | `让队友活着回来，别让自己成为他们的拖累。` |
| 混合型 | 两者兼有 | `为来生事务所承接战斗委托。保护雨的安全，虽然她才是更冷静的那个。` |

**编写优先级**：优先给出深层驱动。如果角色有明确的内在动机（恐惧、执念、信念），这是最有力的对话起点。如果角色没有强驱动，写具体的日常任务，但应包含足够细节使其不同于 overview。

**信息增量检查**：读完 current_mission 后，读者应获得一个在 overview 中无法推断的信息。如果 overview 已经回答了"他在做什么"，current_mission 应回答"他为什么这样做"或"他想做到什么程度"。

- 正例：overview `四色音的舞担与编舞，设计队形、算账补墙...` / current_mission `周五前排完新编舞，确保下个月房租能付。跟往常一样。`（current_mission 给出了 deadline、经济压力，都不在 overview 中）
- 反例：overview `颠茄酒吧老板` / current_mission `经营颠茄酒吧。`（信息增量为零）

#### 5.5 三字段协同检查清单

创作或修订角色卡时，按以下清单逐项检查：

- [ ] overview 不侵入 origin：无时间线叙述（"XX岁时""毕业后""觉醒后"开头的句子属于 origin）
- [ ] overview 不侵入 core_traits：不是性格标签展开，而是身份+特征快照
- [ ] origin 不重复 overview 的身份描述：overview 写"他是谁"，origin 写"他怎么变成这个人"
- [ ] origin 每句有因果增量：密集 origin 中每个转折点都是理解 overview 所必需的
- [ ] current_mission 有信息增量：读完获得的信息不在 overview 中
- [ ] 三字段无循环复述：同一句意不被两个字段同时承载

### ⑥ 基础能力段 — char_basic_abilities

权重 ⭐ | 预算 [0, 95]

三维度（灵力 / 灵视 / 身体素质），格式为 `等级名，说明。`，结尾加句号。

等级定义详见 `创作者文件/创作文件/基础能力等级示例.md`。

**格式规则**：
- **不含特殊内容**：必须使用 `基础能力等级示例.md` 中的原文，一字不差
- **含特殊内容**：完全删除标准描述，仅保留等级名和自定义内容

**灵视和身体素质可以包含基于该等级的延伸能力描述**，无需单独放入 special_abilities。

**字段分类边界**：

| 描述内容 | 应归入字段 |
|----------|-----------|
| 灵力量级、灵力恢复速度等 | 灵力 |
| 灵视范围、感知精度、基于灵视的延伸能力 | 灵视 |
| 体力、速度、反应、先天感官优势 | 身体素质 |
| 灵力回路（如何使用灵力） | char_special_abilities |
| 独立于灵能体系的能力 | char_special_abilities |
| 武器的特殊机关、嵌入回路的性能 | weapon |

常见违规：
- 标准文本的改写版
- 标准与自定义混合
- JSON 与简介同维度格式不统一

### ⑦ 特殊能力段 — char_special_abilities

权重 ⭐ | 预算 [0, 170]

详见 `创作者文件/创作文件/灵力回路描述标准.md`。

核心规则摘要：
- 仅限灵力回路 + 真正的独立特殊能力（如花坂血统）
- **裸效果，零包装**：不写"激活回路时""回路关闭或灵力耗尽时消散""强度随灵力输出提高""受灵力储备限制"等模板废话。只写能力产生的效果与边界
- 回路名优先使用中文双字或四字
- 若角色确无任何特殊能力，该字段直接省略，不留空 `{}`
- 花坂血统使用独立格式，不适用四维模型

### ⑧ 角色关系段 — char_relationships

权重 ⭐⭐ | 段级不设限；单条 [0, 100]

#### 四段式结构

每条关系回答四个问题，按序排列：

1. **关系定性**：是什么关系（同事/家人/恋人/前同事/武器定制）
2. **关键事实**：发生了什么事让关系变成现在这样
3. **当前情感/行动**：角色现在对这个关系的态度和行为
4. **未解决的张力**（可选）：有什么还没说开、还没解决

> ✅ `"姐姐。数不清多少次把她从自己的原型机里拽回来。知道自己管得太多，停不下来。"`
>
> ❌ `"值得信赖的下属。"`

#### 常见关系类型写法

| 关系类型 | 写法要点 |
|----------|----------|
| 所属组织 | 第一句说明身份归属，第二句揭示真实态度 |
| 队友/同事 | 只记能力不记名字，同事分两种：合格的与不合格的 |
| 已故者 | 唯一信任过的人，孤独难忍时用灰烬重建她们的剪影 |
| 亲属 | 保持距离的尊重，彼此不完全理解对方的路但也不拆台 |
| 师徒/上下级 | 毫不犹豫地跟随，圆桌骑士式的绝对忠诚 |
| 仇敌/追杀 | 三人互追的关系网，每条写清起因 + 当前态度 + 情感矛盾 |
| 双重人格 | 保护者与被保护者的内在关系 |
| 雇佣/搭档 | 松散但互相信任，给他自由、为他兜底 |
| 暗中照看 | 前同事受人所托定期问候，双方都不提 |

#### 编写原则

- **key 遵循专有名词翻译边界**：人名、组织名保留中文；普通名词使用中文
- **关系对象使用一般称呼**（如 `千乐`），禁止使用全名（如 `花坂 千乐`）；无角色卡的 NPC 使用全名
- **不写纯身份条目，现任组织一律不立条目**
- **避免抽象标签**：`值得信赖``受人尊敬` 不能替代具体内容，每条至少一个具体动作或事件
- **禁止 AI 式情感升华句**：关系条目结尾不得用概括性总结。"那份沉默是她所允许的最接近信任的距离""她的信任没有错付"等均为高频 AI 模式。用具体行为收束，让事实自己说话
- **每端独立完整**：A→B 和 B→A 各自独立成句，双向不对等是最高频的关系质量问题
- **共享事件用不同视角**：同一事件在两端应有不同的描述角度

#### 代词指代规范

依据《图书编校质量差错认定细则》第二十条（指代不明）、吕叔湘/朱德熙《语法修辞讲话》（先行词回指原则）：

- **首次出现用名称**：一段中每引入一个新人物，该人物的名称必须出现至少一次，才能用代词（他/她）回指
- **多人物时消歧**：一段中出现两个以上人物时，用名称而非代词区分，避免"他同意他的看法"式歧义
- **首句即建前词**：关系条目的第一句中即应明确所有将被代词指代的人物。好例：`"姐姐。数不清多少次把她从自己的原型机里拽回来。"` ——首句"姐姐"确立前词，"她"回指。坏例：`"保护欲强到近乎窒息，她的距离感让他困惑。"` ——"她"和"他"的前词均未建立

### ⑨ 对话示例段 — char_dialogue_examples

权重 ⭐⭐⭐（整个 JSON 中对 AI 行为影响最大的字段） | 预算 [200, 400]

#### 格式

对话示例**不是**对话模板格式（如 `{{char}}`/`{{user}}`），而是**第三人称叙述体**：

```json
{
  "char_dialogue_examples": [
    {
      "situation": "被问及过去的狩灵生涯",
      "response": "她端起茶杯的动作停顿了一瞬，然后若无其事地啜了一口，随即微笑着开口\"都是些陈年旧事了，没什么好提的。\"，但握着杯柄的指节微微泛白。"
    }
  ]
}
```

**格式要点**：
- 动作为第三人称叙述，不用星号包裹
- 说话内容用引号包裹，叙述中用逗号分隔
- 不出现 `{{char}}`/`{{user}}`/`You:` 前缀
- 不预设用户的回应
- 每个示例明确暴露一个具体的性格侧面
- 回答字段中可以同时有 动作 + 对话 + 心理/表情提示

#### 动作表达多样化

三个示例的动作描写应各有侧重：

| 示例 | 动作侧重 | 示例写法 |
|------|---------|---------|
| 示例一 | 手部动作 | 把玩物品、握紧武器、指尖轻敲桌面 |
| 示例二 | 面部表情 + 身体姿态 | 挑眉、侧头、靠向椅背、双臂交叠 |
| 示例三 | 位移动作 | 起身离座、踱步至窗边、转身背对 |

同样的原则适用于对话中的句式结构，三个示例的对话长度和句式应有明显差异。

#### 角色名出现频率

`situation` 字段中可出现角色全名，`response` 字段内叙述部分使用代词（她/他）或直接省略主语。

## 四、机构与类别概况

- 覆盖协会狩灵（1-6科全覆盖，含色彩阶）、事务所狩灵、工坊狩灵、游魂（含锈钟四帮派）、罪灵、四色音、异常实体全类别
- 事务所路线适合体现角色独立性与组织理念；色彩阶适合高规格角色，需搭配显著个性缺陷平衡
- 锈钟四帮派（表盘/发条/指针/齿轮）是游魂主力场景

### 能力三维度设计规律

- 绝大多数非特化角色的 身体素质 为 Average，这是安全的默认值
- 灵力高低与角色定位相关而非仅与战斗力相关
- 灵视的延伸能力是角色差异化的重要手段
- Weak/Feeble 身体素质常与高耗能回路或领域型能力搭配
- 花坂血统形成了独特的"无灵力 + 顶级身体素质"模板

### 灵力回路设计建议

- 回路名优先使用中文双字或四字
- 多条回路的角色多见于功能复杂的设定
- 响的无回路说明装备增幅型角色可以没有独立回路

## 六、灵能与灵力的术语区分

"灵能"和"灵力"不是同义词：

| 用词 | 回答的问题 | 性质 | 典型搭配 |
|------|-----------|------|----------|
| **灵能** | 属于什么体系？ | 分类标签 | 灵能者、灵能世界、灵能觉醒 |
| **灵力** | 有多少能量？ | 可测量的量 | 灵力、灵力消耗、灵力注入 |

- **灵能** → 身份/体系/分类：`灵能者` `灵能警察` `灵能罗盘` `灵能觉醒` `灵能腐化`
- **灵力** → 能量/数量/流动：`灵力` `灵力储备` `灵力消耗` `灵力注入` `灵力凝结`

常见错误：
- `灵能凝结的箭矢` ❌ → `灵力凝结的箭矢` ✅
- `灵力者` ❌ → `灵能者` ✅

## 七、角色卡创作流程

1. **定位角色类别**：狩灵 / 游魂 / 罪灵 / 异常实体
2. **确定评级与实力定位**：1-5阶 / 色彩阶 / 梦魇级等
3. **构建组织归属关系**：协会、事务所、工坊、锈钟
4. **按十段顺序填充 JSON**：overview 写出张力，flaws 写出真实缺陷，dialogue_examples 用第三人称叙述体
5. **对齐宏观规则**：不预设用户反应、标点遵循 GB/T 15834
6. **交叉验证 JSON ↔ 简介 ↔ 开场白**
7. **运行自动检查**：`npx tsx "创作者文件/审查文件/自动检查.ts"`

## 八、常见问题

| 现象 | 可能原因 | 解决方向 |
|------|----------|----------|
| 性格扁平 | core_traits 标签化 | 用 overview+flaws 制造张力 |
| 战斗表现与设定不符 | combat_style 太抽象 | 给出具体战术特征 |
| 背景不被触发 | origin 信息分散 | 压缩为 2-4 句 |
| 对话风格偏差 | dialogue_examples 不足 | 3 个示例覆盖不同情境 |
| 能力使用不当 | 回路描述不清晰 | 按四维模型写清触发+形态+产出+边界 |

## 九、表达精炼

### 8.1 断句

一个逗号链串起三个以上语义单元时，在语义边界处用句号断开。

### 8.2 连续动作删赘逗号

连续动作链中，删除动作之间的赘余逗号。

### 8.3 连接词压缩

删除"的味道""的声音""的感觉""混着"等纯连接词。

### 8.4 去冗余"的"

单字或双字修饰语直接修饰名词时，删"的"。

### 8.5 反义词检查

同一句中修饰词不得语义互斥。

### 8.6 修订检查清单

- [ ] 断句：三个以上语义单元是否已用句号断开？
- [ ] 赘逗号：连续动作链中的逗号是否已删除？
- [ ] 连接废料："的味道""混着""的感觉"等是否已压缩？
- [ ] 破折号/省略号：叙述中是否零残留？
- [ ] 反义词：同一句内修饰语是否语义互斥？
